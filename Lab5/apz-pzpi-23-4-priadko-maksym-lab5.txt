2 ЗАВДАННЯ
На цій роботі необхідно зробити коротку презентацію цілісного проекта який ви реалізували в ході двох семестрів роботи. Необхідно підготувати демо (4-6 хвилин) основних функцій проекту (записати на відео заздалегідь), розказати що із запланованого ви встигли зробити, а що — ні.

3 ОПИС ВИКОНАНОЇ РОБОТИ

3.1 Опис системи
PythonWiki це інформаційно-освітня програмна система, призначена для створення, перегляду, редагування та систематизації навчальних матеріалів з мови Python. Система поєднує можливості вікі-платформи, навчального середовища та графової бази знань, у якій статті можуть бути пов’язані між собою логічними зв’язками.
3.2 Технічні рішення, які роблять масштабування можливим
Серверна частина: REST API на ASP.NET Core / .NET 8; SQL Server для збереження користувачів, ролей, статей, курсів, прогресу навчання, зв’язків між статтями та журналу активності; Entity Framework Core для роботи з базою даних; JWT-автентифікація та refresh-токени; рольова модель доступу; управління користувачами, статтями та курсами; механізм нарахування XP за навчальну активність; побудова графа знань між статтями; API для IoT-компонентів; Swagger-документація; підготовка до контейнеризації та масштабування.
Веб-клієнт: SPA на React/TypeScript; реєстрація та авторизація користувачів; перегляд списку статей; пошук навчальних матеріалів; відкриття й читання статей; завершення статей із нарахуванням XP; перегляд навчальних курсів; перегляд графа знань; створення та редагування статей користувачами з відповідними правами; адміністрування користувачів; зміна ролей; налаштування адреси backend API; перемикання мови інтерфейсу.
Мобільний клієнт: Android-застосунок на Kotlin; авторизація користувача; перегляд навчальних матеріалів; робота зі статтями та курсами; перегляд прогресу користувача; синхронізація з backend API; доступ до основних функцій системи PythonWiki з мобільного пристрою.
Інтеграція ШІ (наступні релізи): рекомендації статей і курсів на основі прогресу користувача; автоматичне формування навчального маршруту; інтелектуальний пошук за змістом статей; генерація прикладів коду; перевірка та пояснення фрагментів Python-коду; автоматичне визначення пов’язаних статей для побудови графа знань; модерація та покращення якості навчальних матеріалів.
3.3 Реалізовані функції
Серверна частина:
– реалізовано backend на ASP.NET Core / .NET 8 з використанням Entity Framework Core та SQL Server;
– створено основні моделі даних: користувачі, ролі, статті, курси, прогрес користувача, refresh-токени, зв’язки між статтями, журнал активності та IoT-дані;
– реалізовано JWT-автентифікацію, refresh-токени, рольову модель доступу та базові адміністративні можливості;
– реалізовано контролери й сервіси для авторизації, користувачів, статей, курсів, XP, графа знань, IoT та перевірки стану системи;
– додано Swagger-документацію, автоматичне застосування міграцій і початкове наповнення бази даних.
Web-клієнт:
– створено React SPA на TypeScript із централізованою взаємодією з backend API;
– реалізовано реєстрацію, авторизацію, вихід із системи та відновлення сесії;
– реалізовано перегляд, пошук, відкриття, створення й редагування статей;
– реалізовано роботу з курсами, графом знань і завершенням статей із отриманням XP;
– реалізовано адміністрування користувачів, зміну ролей, налаштування адреси backend API та перемикання мови інтерфейсу.
Мобільний клієнт:
– створено Android-клієнт на Kotlin із базовою структурою мобільного застосунку;
– реалізовано взаємодію з backend API;
– реалізовано основні сценарії доступу до навчальних матеріалів, статей, курсів і прогресу користувача.
3.4 Заплановані, але не виконані функції
– Повноцінна інтеграція ШІ в навчальний процес — у межах поточного MVP було лише спроєктовано сценарії майбутнього використання ШІ, але не реалізовано рекомендаційну систему, генерацію матеріалів і автоматичне пояснення коду.
– Автоматична генерація графа знань за допомогою ШІ — зв’язки між статтями реалізовані як частина логіки системи, але автоматичне визначення семантичних зв’язків між матеріалами перенесено на наступні релізи.
– Повноцінна система колективного редагування в реальному часі — реалізовано створення та редагування статей, але одночасне редагування кількома користувачами не входило до скоупу MVP.
– Складна система модерації контенту — рольова модель і адміністрування користувачів реалізовані, але автоматична модерація та гнучкі workflow перевірки матеріалів залишені для подальшого розвитку.
– Повноцінна офлайн-робота мобільного клієнта — мобільний клієнт створено як базовий застосунок, але повний офлайн-режим із локальним кешем і синхронізацією змін не реалізовано.
– Масштабування бази даних — масштабування виконано для stateless API-рівня, тоді як SQL Server залишено одним сервісом, оскільки горизонтальне масштабування бази даних потребує окремих механізмів реплікації, шардингу або керованого кластерного рішення.
– Повноцінна production-інфраструктура — реалізовано навчальне Kubernetes-розгортання, але моніторинг, централізоване логування, CI/CD pipeline, TLS-сертифікати та production-grade secrets management потребують додаткового налаштування.

4 ВИСНОВКИ
У результаті роботи протягом двох семестрів було сформовано та частково реалізовано цілісну програмну систему PythonWiki, призначену для обміну знаннями та практичними навичками програмування мовою Python. У межах проєкту було розроблено концепцію системи, визначено її бізнес-вимоги, скоуп первинного випуску, можливості наступних релізів і обмеження.
Було реалізовано серверну частину на ASP.NET Core / .NET 8 з базою даних SQL Server, JWT-автентифікацією, рольовою моделлю, модулями статей, курсів, XP, графа знань, користувачів, адміністрування та IoT. Також було створено web-клієнт на React / TypeScript, який забезпечує основні сценарії роботи користувача: реєстрацію, авторизацію, перегляд і пошук статей, роботу з курсами, перегляд графа знань, створення матеріалів і адміністрування користувачів.
